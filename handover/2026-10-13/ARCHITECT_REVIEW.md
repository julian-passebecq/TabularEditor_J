## Boundaries (question 2): no violation found
- Core has no WinForms, TOM, AMO, HTTP or Newtonsoft imports. S6 replaced the planned Newtonsoft pin with a bounded reader; that choice is documented and makes neutrality stronger.
- The Disk, Loaded, Live, Git and Baseline stamps are distinct types. Unknown PBIR schemas are read-only, enforced by `ThemeApplyPlan.cs:41`.
- No sandbox claim anywhere. Only the companion references `TE2Enhanced.Mcp`, and it is not in the sln. The doc's net8.0 + RollForward matches the csproj; only the PLAN still says "net10".
- Qualification: **TE2's own Save is not hooked** (S5). The AGENTS rule "no silent overwrite" holds for PbiBench writes. It does not hold for a TE2 model save over TMDL files edited outside TE2: there is only an after-the-fact "Review save target" check. That is upstream behaviour, not a regression, but the V1 claim must say so.

## V1 gaps (question 3)
1. A pre-save conflict prompt on TE2 Save, which needs a product decision on touching the upstream save path.
2. Recovery that is safe with several instances (#1).
3. No retention or delete UI for `%LOCALAPPDATA%\TE2Enhanced\journal`. Backups of report.json stay there indefinitely. The location is disclosed but never pruned.
4. Nothing verified natively or live yet: Desktop/XMLA, the positional arguments passed to DAX Studio, Power BI Desktop accepting a spliced report.json, an MCP client round trip.
5. PBIR-Legacy, bookmarks and report-level measures are not indexed (they show as Unresolved). Recipes cover measures only.
6. Integration branch only: per the slice notes, nothing is pushed or merged. CI on `9160fd7` was not checked in this review.

## Fixes applied (branch `claude/pbibench-review-fixes`, 2026-10-13)
1. YELLOW RecoveryStore multi-instance: **fixed**. Each manifest records its owner (pid + process start time UTC, `RecoveryOwner`); `ListRecoverable` offers only copies whose owner is gone (pid not running, or running with another start time) or that this process released (window closed/disposed); a live other instance's draft is never offered, overwritten or deleted. Restore = `Adopt` (new id written and verified, then the source removed). Save / Don't save / close use `DeleteOwn` (this process only); the explicit Delete menus skip a running instance's drafts. Applied to the DAX workbench and the script workspace. Opt-in, retention and new-file-only writes (no File.Replace, OBS-001) unchanged. Smokes: Core `RecoveryOwnershipSmoke`; Host `DaxRecoverySmoke`, `ScriptWorkspaceSmoke` (multi-instance part).
2. YELLOW ReviewedFilePlan re-hash: **fixed**. Each target is re-hashed (Create: re-checked absent) right before its own commit/delete; a mismatch throws `ReviewedFileChangedExternallyException` (message names the file), the files before it are rolled back and the external edit is kept. Smoke: Core `ReviewedFilePlanReviewFixesSmoke` (replace, delete and create targets).
3. LOW Mark(Applied) after commit: **fixed**. A marker failure returns `Applied` with `ReviewedFilePlanResult.Warning`; the journal reads as interrupted and still restores; the theme form says "Applied … Warning:" and keeps "Restore this apply" enabled. Smokes: Core `ReviewedFilePlanReviewFixesSmoke`; Host `ThemeApplySmoke` (marker scenario).
4. LOW RestoreLast exceptions: **fixed**. `InvalidDataException` and every other non-fatal exception are shown in the form. Smoke: Host `ThemeApplySmoke` (damaged backup, damaged journal).
5. LOW theme file name clash: **fixed**. `ThemeApplyPlan.Create` refuses when the derived file name is already used (name or path) by a RegisteredResources item that is not a CustomTheme, naming the file and the item type. Smoke: Core `ThemeApplyPlanSmoke` (clash part).
6. LOW watcher error: **fixed**. A non-overflow `Error` recreates the FileSystemWatcher (rescan signal, `Restarts`); when the root is gone the watcher stops with `ProjectWatcherState.RootMissing` and a `RootMissing` signal, and the Project window shows a banner. `ProjectWatcherSmoke` now asserts that no signal names an ignored path and that the first signal naming a burst file carries all 20 (no "no signal at all" assertion). Smoke: Host `ProjectWatcherSmoke`.
- V1 gap 3 journal retention: **fixed**. Core `ReviewedFilePlan.ListJournalInfos / SelectPrunableJournals / PruneJournals (default 30 days) / DeleteJournal`; only Applied/RolledBack/Restored journals are pruned or deleted, never Applying, incomplete or unreadable ones; only journal-owned files are removed. Restore window: "Delete old journals…" with confirmation. Smokes: Core `JournalRetentionSmoke`; Host `ProjectWindowSmoke` (delete old journals part).
- Note: OBS-001 (`File.Replace` refused, ERROR_UNABLE_TO_REMOVE_REPLACED) was frequent on this machine during the session, including in untouched code (`DaxDocument.Save` in `DaxDocumentIdentitySmoke`). The new Core smokes repeat a scenario once on a spare fixture when an apply hit OBS-001 and rolled back; product save paths still never retry or wait.
- Verification: `Scripts/Verify-PbiBench.ps1` exit 0, 8/8 stages PASS (evidence `.tools/verify-fixes`, git-ignored); host smoke repeated 5 more times: 5/5 exit 0 (one repeat logged an OBS-001 skip of the damaged-journal theme scenario).
