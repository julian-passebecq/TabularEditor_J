## Implemented
- **EXP-002 bounded profiling drafts** — Core `PbiBench.Core/Explore/DaxProfileQueryBuilder.cs`: column profile (ROW of COUNTROWS / DISTINCTCOUNT / COUNTBLANK, MIN/MAX only for numeric/date, then `TOPN(n, SUMMARIZECOLUMNS(col, "Rows", COUNTROWS(t)), [Rows], DESC)`) and relationship coverage (many-side rows/distinct/blank keys, unmatched keys `EXCEPT(DISTINCT(many), DISTINCT(one))`, unused one-side keys, then `TOPN(n, unmatched)` samples). Names escaped by `DaxTablePreview.QuoteTable/QuoteColumn` (same validation: no CR/LF/NUL, ≤ 512 chars). Header comments never embed object names. Host `TabularEditor/PbiBench/Explore/PbiBenchProfileForm.cs` (mode, table/column or relationship, limit; data type → value kind) + command `PbiBench_ShowProfileDraft` opens the text with the existing `PbiBenchDaxWorkbenchForm.LoadPreviewDraft` (unsaved document, row cap = limit). Nothing executes until F5; F5 is refused when the handler changed or the profiled table/column/relationship was renamed/removed (`ExecutionContextIsCurrent`).
- **OPT-001 curated BPA pack** — `TabularEditor/PbiBench/Optimize/PbiBenchCuratedRules.cs`: 7 rules as C# constants, IDs `TE2E_DAX_DIVISION`, `TE2E_DAX_IFERROR`, `TE2E_FLOAT_COLUMN`, `TE2E_NUMERIC_SUMMARIZE`, `TE2E_NAME_WHITESPACE`, `TE2E_DATE_TABLE`, `TE2E_MEASURE_FOLDER` (category "TE2 Enhanced curated", no FixExpression). Applied through `Analyzer.GetEffectiveRules(..., additionalRules)` so same-ID user/machine/external/model rules win. Fresh rule instances per run; loaded user rules are copied (`AssignFrom`) so TE2's background BPA state is never shared. No rule file, ignore list or annotation is written.
- **OPT-001 semantic assertions** — Core `PbiBench.Core/Optimize/SemanticAssertion.cs`: `ASSERT-FMT` (visible measures have FormatString or FormatStringExpression), `ASSERT-REF` (rows of S2 `SemanticUsageIndex.Unresolved`), `ASSERT-BIDI` (both-direction relationships unless allowlisted by name or `From -> To`/`From → To`, case-insensitive), `ASSERT-KEY` (many-side/FromColumn keys hidden, column or table), `ASSERT-DESC` (visible measures have a description). Host `Optimize/PbiBenchModelChecks.cs` maps TOM → neutral facts via a fresh `PbiBenchSemanticSnapshot`; `Optimize/PbiBenchAssertionsForm.cs` lists both groups, Enter/double-click/"Go to object" → TE2 `Goto` (refused for removed objects or a changed handler). Allowlist box is prefilled from the optional model annotation `TE2Enhanced_BidirectionalAllowlist` (read only).
- Menu `Navigation/PbiBenchMenu.Explore.cs` (Tools > PbiBench: "Profile column / relationship coverage (query draft)…", "Model checks: curated BPA + assertions…"); commands `Navigation/UIController.PbiBench.Explore.cs`. ## Exact limits
- Drafts bound returned rows only (top values 1-100, samples 1-1000); COUNTROWS/DISTINCTCOUNT/EXCEPT scan whole columns server-side. Coverage counts real blank many-side keys as unmatched when the one side has no blank; DISTINCT ignores the virtual blank row. Multi-column / non-SingleColumn relationships are not offered.
- The Workbench status line says "Table preview draft" (existing `LoadPreviewDraft` text; S7 does not edit the Workbench partials).
- Curated rules are heuristics: `TE2E_DAX_DIVISION`/`IFERROR` are regex over raw DAX (comments/strings not excluded). `TE2E_NUMERIC_SUMMARIZE` flags visible numeric data columns including amounts meant to sum.
- ASSERT-REF inherits S2 lexical limits (advisory, no binder). ASSERT-KEY checks FromColumn only (one-side keys and IsKey columns are not required hidden, to avoid date-table false positives). Findings and rows capped at 5,000 (counts stay exact).
- The allowlist is per dialog run; saving it into the annotation is not offered (would be a model write).
