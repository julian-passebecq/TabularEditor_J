# S6 Report — PBIR index, lineage, reviewed theme apply (REPORT-001/002)

Branch `claude/pbibench-s6-report` from `d652e0f`. Not pushed, not merged. Verify: `Scripts/Verify-PbiBench.ps1`, evidence `.tools/verify-S6` (git-ignored).

## Decision: JSON in Core
No Newtonsoft.Json in PbiBench.Core. A bounded reader `Report/PbirJson.cs` (RFC 8259, depth 96, 2M values, 32M chars) keeps Core package-free (the
netstandard2.0 Newtonsoft asset would otherwise be copied next to the host's net45 13.0.3 copy) and gives exact source spans, which the theme writer
needs to splice report.json without re-serializing it. Existing Core JSON (DataContractJsonSerializer) is typed-only and unsuited to arbitrary PBIR.

## Implemented
- **REPORT-001 index** — `PbiBench.Core/Report/PbirSchemaRegistry.cs` (curated `$schema` registry: report 1.0.0–3.0.0, page 1.0.0–2.0.0,
  visualContainer 1.0.0–2.1.0, pagesMetadata/versionMetadata 1.0.0, definitionProperties 1.0.0/2.0.0; anything else = unknown),
  `PbirReportIndex.cs` (definition.pbir byPath link, version.json, report.json theme + report filters, pages in pageOrder, page filters, visuals:
  queryState projections per role, sortDefinition, objects/visualContainerObjects formatting, visual filters, visual groups; malformed/oversized
  files become diagnostics; `FindReportsFor(X.SemanticModel)`), `PbirFieldReference.cs` (Column/Measure/Aggregation→column/Hierarchy/HierarchyLevel,
  auto date `PropertyVariationSource` → base column, `SourceRef.Source` alias kept as alias).
- **REPORT-001 lineage** — `Report/ReportLineage.cs` against S2 `DaxModelNameSet` (+ optional table→hierarchy names). Resolved = table and object of
  that kind exist (case-insensitive). Unresolved = table/object missing (hint when the measure lives on another table). Ambiguous = query alias,
  column/measure kind mismatch, or hierarchy without supplied hierarchy names. Bound to `ModelRevision`; `MeasureUses()` feeds the Usage tab.
- **REPORT-002 theme apply** — `Report/ThemeApplyPlan.cs` builds a S5 `ReviewedFilePlan`: Replace `definition/report.json` (before-hash = the
  bytes read at index time), Create/Replace `StaticResources/RegisteredResources/<name>.json`, Delete the previously registered custom theme file.
  report.json is spliced: only the `themeCollection` and `resourcePackages` values are rewritten (BOM, CRLF, indentation, other bytes kept;
  result re-parsed before writing). Refused (`ThemeApplyRefusedException`) unless every schema seen is known, report.json is a writable version,
  version.json is 1.0.0/2.0.0 and themeCollection exists; theme must be UTF-8 JSON object with `name`, ≤ 1 MB. Restore = journal, byte-exact.
- **Host** — `TabularEditor/PbiBench/Report/PbiBenchReportForm.cs` (summary, Lineage tab with state filter + navigation via TE2 `Goto`, Pages and
  visuals, Diagnostics, Apply theme…, Restore journal…), `PbiBenchThemeApplyForm.cs` (file changes with hashes/sizes, themeCollection before/after,
  confirm default Cancel, apply, "Restore this apply"), `PbiBenchReportBinder.cs` (TOM hierarchies, object resolve, PBIP report discovery next to
  the loaded `X.SemanticModel`; `PbiBenchReportUsage` holder), `PbiBenchSemanticViewForm.ReportUsage.cs`, `Navigation/PbiBenchMenu.Report.cs`
  (Tools > PbiBench > "Report (PBIR) index and lineage…"), `Navigation/UIController.PbiBench.Report.cs`. Journals: S5 `%LOCALAPPDATA%\TE2Enhanced\journal`.
- **Usage tab hook (S2 files, 2 lines)** — `PbiBenchSemanticSnapshot.BuildUsage` passes `PbiBenchReportUsage.GetMeasureCounts(...)` as external
  counts; `PbiBenchSemanticViewForm.Usage.cs` calls `InitializeReportUsage(layout)` ("Used in report" column + summary). Counts appear only after the
  report form indexed a report against the same model name revision; any rename/add/delete withholds them (unknown, not stale).
- No upstream TE2 file edited (UPSTREAM_TE2_SYNC.md unchanged). No network, no persistence besides plan journals.

## Exact limits
- Index: 500 pages, 1,000 visuals/page, 10,000 visuals, 200,000 field uses, 8 MB/file, 256 MB total, 500 diagnostics, 50 locations per lineage row.
  Runs synchronously on the UI thread when the form opens or "Index" is pressed.
- PBIR-Legacy (single report.json) and bookmarks/report extensions (measures defined in the report) are not indexed; extension measures show as
  Unresolved. Hierarchy levels and visual calculations are not checked. Names only: no engine query, no field-parameter expansion.
- Theme apply writes only the custom theme; base theme, images and visual-level formatting are untouched. Old custom theme file is deleted
  (restorable). The schema registry is a curated list; a newer valid report stays read-only until the list is extended.
- OBS-001 still open: ReviewedFilePlan's File.Replace was refused (another process holding a file written ~100 ms earlier) in some smoke runs;
  apply then fails once and rolls back byte-exact, no retry. Both theme smokes accept that once (rollback verified), then repeat on a second fixture.
