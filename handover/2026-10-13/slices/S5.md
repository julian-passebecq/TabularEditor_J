## Implemented

Create/Replace/Delete with exact SHA-256 before-hash; `Preview()`; `Apply(journalRoot)` = stale check (nothing written) → backups into `<journalRoot>/<planId>/` → per file sibling temp write + `File.Replace`/`Move` → on first failure roll every file back from backups. `Restore(journal)` previews first and refuses (writes nothing) when any file changed after apply; works for Applied and interrupted journals. ## Deferred / limits (honest)
- **TE2 Save is not hooked.** No pre-save prompt: hooking upstream `UIController_Files` save is invasive and OBS-001 forbids changes in save paths. After a TE2 Save its own writes appear as changes until "Accept". No upstream TE2 file was edited (no UPSTREAM_TE2_SYNC row needed).
- Models opened before the menu installs (e.g. command-line open) have no load baseline → "NoBaseline" with an accept action, never assumed clean.
- Baseline in the Project window is per window session (in memory), not persisted.
- Rollback leaves newly created empty parent folders. No retries or waits: a forward write whose atomic replace is refused fails once and rolls back. Observed locally: Windows can refuse `File.Replace` (ERROR_UNABLE_TO_REMOVE_REPLACED) on a file replaced milliseconds earlier while in-place writes succeed (scanner holding it without delete sharing). So recovery writes only (rollback/restore) fall back once to a verified in-place overwrite to get the original bytes back. Smokes use distinct files per scenario for this reason; related to, not a fix for, OBS-001.
- No ReviewedFilePlan producer ships in S5 (S6 theme apply is the first); the restore window is exercised by the smoke.
