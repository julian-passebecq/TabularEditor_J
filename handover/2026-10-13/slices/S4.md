## Exact limits
- Scripts are trusted, in-process, NOT sandboxed; the advisory scan is keyword-only. Trust is per document version, in memory.
- Each compile loads a new in-memory assembly (same as TE2; not unloadable in .NET Framework).
- Script workspace is modal; run is refused if the TE2 model handler changed since it opened.
- Rollback covers model changes only. `ScriptHelper.AfterScriptExecution` is kept, so a script that queued `FormatDax`
  still calls TE2's existing formatter path (TE2 behaviour, user code).
- Script file save is a plain `File.WriteAllText` (user file, not atomic). Recovery opt-in marker `recovery.optin`.
- Recipes: 10,000 measures, 1,000 targets, rename single target and 2,000 dependent properties; values per catalog
  (folder 1,024, format 512, description 4,000, name 512). Rename refusal is conservative: textual `[Name]` in strings,
  comments, KPIs or same-named columns of other tables blocks it. Reports/external tools are not rewritten.
- The host smoke calls `ScriptEngine.InitScriptEngine` (as TE2 startup does): it may refresh
  `%LOCALAPPDATA%\TabularEditor\TOMWrapper14.dll` and would compile a `MacroActions.json` if one exists.
